# Магазин цифровых товаров (Монорепозиторий)

Это проект магазина цифровых товаров, разделенный на монорепозиторий (Frontend + Backend + Shared Packages).

Документация по выполненным задачам разделена на два файла для удобства:
👉 [**Задание 1 (Прошлая неделя)**](./TASK_1.md) — Описание первого этапа (Витрина, базовый флоу покупки, выдача ключа).
👉 [**Задание 2 (Текущие задачи)**](./TASK_2.md) — Описание текущих этапов (Живая витрина SSE, Решение проблем Race Conditions, Сбои и админка, Промокоды).

## Структура репозитория

```text
project/
├── apps/
│   ├── frontend/   # Vite + React (UI)
│   └── backend/    # NestJS + TypeORM (API)
├── packages/
│   ├── shared/     # Общие типы и интерфейсы (TypeScript)
│   └── config/     # Общие настройки (ESLint, TS)
├── .env            # ЕДИНЫЙ глобальный конфигурационный файл
├── package.json
├── pnpm-workspace.yaml
└── docker-compose.yml
```

## Стек технологий

- Менеджер пакетов: **pnpm workspaces**
- Язык: **TypeScript**
- Frontend: **React + Vite** (Vanilla CSS Variables, Zustand)
- Backend: **NestJS** + **TypeORM**
- База данных: **PostgreSQL**

## Как запустить проект

У вас есть два удобных способа запуска проекта: локально (для разработки) или полностью через Docker.

### Подготовка (ОБЯЗАТЕЛЬНЫЙ шаг)
Перед любым запуском **строго обязательно** создать файл `.env` в корне проекта. Без него приложение не запустится.
Вы можете просто скопировать готовый пример:
```bash
cp .env.example .env
```
*(В файле `.env.example` уже прописаны все нужные настройки для тестовой базы и портов)*

### Способ 1: Локальная разработка (pnpm dev)
Этот способ удобен для написания кода. Он автоматически поднимет базу данных PostgreSQL в фоне (через Docker), а затем запустит локальные серверы (Фронт и Бекенд) с горячей перезагрузкой.
```bash
pnpm install
pnpm dev
```
*(При первом запуске бекенд автоматически создаст таблицы в базе данных и заполнит их товарами и ключами для тестов).*

### Способ 2: Полностью через Docker (Все в контейнерах)
Если вы хотите запустить проект максимально изолированно, вы можете поднять всё (Фронтенд, Бекенд и БД) в контейнерах:
```bash
pnpm run docker
```
*(Это выполнит команду `docker compose up --build`).*

Чтобы остановить и удалить контейнеры, используйте команду:
```bash
pnpm run docker:down
```

## Доступные URL-адреса

- **Фронтенд (Витрина)**: [http://localhost:5173](http://localhost:5173)
- **Фронтенд (Админка)**: [http://localhost:5173/admin](http://localhost:5173/admin) *(Панель восстановления проблемных заказов)*
- **Бекенд (API)**: [http://localhost:3001](http://localhost:3001)
- **Swagger (Документация API)**: [http://localhost:3001/api/docs](http://localhost:3001/api/docs)

### Основные API-эндпоинты:
- `GET /api/products` — список товаров.
- `POST /api/orders` — создание заказа.
- `GET /api/orders/:id` — получение статуса заказа.
- `POST /api/orders/:id/pay` — имитация успешной/неуспешной оплаты.
- `POST /api/webhook/payment` — вебхук для обработки статусов платежей.
- `POST /api/orders/:id/apply-promo` — применение промокода к заказу.
- `GET /api/admin/recovery-orders` — заказы, ожидающие ручной выдачи ключа.
